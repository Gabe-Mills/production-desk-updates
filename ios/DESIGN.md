# Production Desk mobile design

**Thesis:** a precise, quiet production instrument. The screenplay is the hero; Squid red identifies creation and the current section. Preserve the brand while making the phone feel intentional.

The original SP mark, Production Desk wordmark, Futura/Courier type stacks, white paper, pink scene accents and `#E60026` remain. No new identity or third-party imagery was introduced. Headings gain scale and tighter spacing; hairline rules and tabular production counts replace extra containers. A restrained 12-point corner radius groups editing panels without making each field a card.

On phones, the compact brand and production picker precede a concise workspace heading. All five sections stay in a bottom bar with full accessible names and one current destination. Import, production creation, settings and help live in an explicit tools disclosure. Script search expands on demand and tagging follows the script, so the scene reaches the first screen. Tablet widths retain the sidebar and use a split script/breakdown view when space permits. Dark mode uses the existing semantic palette; reduced motion disables transitions.

## Reference decisions

| Reference | Principle retained | Adaptation |
| --- | --- | --- |
| Original tracked Production Desk 1.4.1 release | Squid mark, red, Futura/Courier, screenplay and scene-color semantics | Preserve the source assets and workflows; compose them for touch |
| [Teenage Engineering industrial catalogue](https://styles.refero.design/style/aecf9dda-5cba-4dc7-9e73-59b65d895cdf) | Neutral space, sharp type hierarchy, sparse accent, precise rules | Use Squid's own type and red; keep controls legible rather than copying tiny catalogue text |
| [Apple tab bars](https://developer.apple.com/design/human-interface-guidelines/tab-bars) and [UI design tips](https://developer.apple.com/design/tips/) | Stable top-level destinations, clear labels, generous touch targets | Five labeled destinations; full accessible names; disclosure for secondary commands |

Visual review uses real simulator screenshots and WKWebView geometry, alongside import/edit/navigation tests. [DESIGN-REVIEW.md](DESIGN-REVIEW.md) records review criteria and [VERIFICATION.md](VERIFICATION.md) records the executed checks. Physical-device, VoiceOver and large-text testing remain owner follow-up before wider distribution.
